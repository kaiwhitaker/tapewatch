# Rubric — Monitor issue (grade every issue before publish; Fridays re-grade)
1. One sharp finding leads; a reader gets the point in 60 seconds.
2. Every verdict-driving number from a named metrics.py function, two-sourced.
3. Tape table: consistent metrics, single timestamp, benchmark-relative column.
4. Each WATCH names the observation that would resolve it (+ [S,C] from #2).
5. DRIFT only with a prior-issue baseline. Issue-boundary universe rule respected.
6. "We said → what happened" section reports against every prior on-record call.
7. Voice rules hold (lint.py passes); zero intent accusations; disclaimer verbatim.
8. 1,500–2,500 words; [TBD]s are explicit promises with an issue number attached.
9. At least one finding nobody else publishes (derived cross-venue metric).
10. Reproducibility offer present; snapshot committed same day.
